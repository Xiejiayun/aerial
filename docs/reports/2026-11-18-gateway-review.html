04 / 是否发布 npm 包？

有条件建议 值得发布这批改动，但当前提交不是可原样发布的版本。官方 registry 的 latest 是 0.3.9，清单仍是同一版本。仓库的 0.A.B 规则在 B=9 后递增 A 并把 B 重置为 1，下一候选是 0.4.1，不是 0.3.10。

  1. 先确认直接访问适用。使用受限网络的用户应保留 0.3.9，除非确认能直接连接 GitHub/Copilot。愿意切换时取消 AERIAL_UPSTREAM_PROXY，仅删除报错所指配置文件中的 upstreamProxyMode、upstreamProxyEndpoint、upstreamProxySource；保留其他配置和凭据。既有服务升级后重新安装并重启。
  2. 准备独立版本 PR。同步两个清单和变更日志，明确 CLI 命令及出站路由的破坏性变化。经授权后，用真实订阅在直连环境验证至少一个会话和一个有权限的图片端点；若账号无图片权限，明确记录，不认作通过。
  3. 从干净的 main 发布。复核官方 registry 与标签，执行 npm run release:preflight -- --expected-version 0.4.1；通过后另行授权按发布手册走标签和 CI。遇到升级阻断可退回 npm install -g @jiayunxie/aerial@0.3.9，还原事先备份的旧路由设置并刷新服务；不要覆盖其他客户端配置。

证据来源：合并后 CI 的官方 npm 查询与审计（latest 0.3.9、锁文件审计 0 项已知漏洞）。本机无缓存直连 registry 时 TLS 握手失败；没有把本机缓存返回的旧 dist-tag 当成发布依据，也没有关闭 TLS 验证。
